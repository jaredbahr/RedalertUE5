# Command-card validation controller

PR72 preparation only. This controller has not compiled or run the command card in Unreal. It never verifies physical input or clears PR71 acceptance. Its default invocation prints preparation requirements and launches nothing.

`run-stage.ps1` offers fixed `Build`, `NativeHUD`, `Render1280`, `Render960`, `Input1280` and `Input960` cases. Execution requires all of the following:

- A clean isolated source checkout, exact Git/C++ identities and the complete committed source manifest. Every source path/blob must match Git, not just a selected subset. Installed editor paths must match the bound engine root. The fourteen intended authored-content paths/bytes/hashes, including both maps, must match `authored-content.json`.
- A separately recorded independent review approving that exact binding SHA256. `prepare-bindings.py` writes `REVIEW_REQUIRED.json` with `approved=false`; it cannot grant approval.
- Current coordinator confirmation that owned lanes are drained, no competing game or validator, and actual hashed qualification/admission receipts.
- A full 600-second quiet window **before** an unextended 20-minute stage reservation, followed by fresh dispatch admission. Resource-only samplers retain their original frozen identity; their receipts never become PR72 gameplay evidence.

## Binding and receipt format

First prepare and load the exact watchdog with `prepare-watchdog.ps1` in an admitted bounded capability-preparation slot, using the reviewed source head/hash. This uses PowerShell's documented [assembly-output and load operations](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.utility/add-type?view=powershell-7.6). Preparation precedes functional dispatch and does not launch Unreal or establish acceptance. Retain its assembly/hash/module identity, receipt and returned in-memory capability object. The dispatcher requires that already loaded capability; it cannot compile a watchdog during controller setup.

`prepare-bindings.py --help` lists the required local paths, including the prepared watchdog receipt. It only reads committed source, binaries, existing content and the original resource samplers. It writes a private binding for the chosen future runtime root; it neither materializes that root nor invokes Unreal. Keep these path-bearing files outside public Git.

The prerequisite JSON contains hashed file references shaped as `{"path":"absolute local file","sha256":"lowercase SHA256"}` under `readiness`, `readinessOutcome`, `admission`, `admissionOutcome` and `lease`. Native outcomes are the supervisor's **returned** outcome, including receipt-write completion, rather than an earlier raw exit file. The lease records `head`, `ownedLanesDrained=true`, UTC `createdUtc`/`expiresUtc` exactly 1,200 seconds apart and a local `cancelPath`. Creation follows qualification; dispatch admission follows creation and is no older than 60 seconds.

After a genuinely successful build, add `build` (`PAYLOAD_RESULT.json`), `buildOutcome` (`INNER_RESULT.json`) and `buildTerminal` (`RETURNED_OUTCOME.json`) to the next prerequisite bundle. The terminal native outcome must show successful exit of the entire fresh controller, zero survivors and exact hashes of the proof, inner result and `CONTROLLER_COMPLETE.json`. Every layer must agree on source head, reviewed binding digest and C++ tree. The checker also reconciles the common case directory, build interval, fresh DLL/module bytes and BuildId. An inner success followed by controller failure/stall cannot be reused. Valid same-binding build reuse across separate reservations remains supported. Empty, stale, truncated, changed, forced-cleanup and incomplete receipts fail closed.

In the prepared dedicated parent host, pass the reviewed binding, independent review, actual prerequisite bundle/hashes, source/C++ identities, returned `-WatchdogCapability` object and exact lease expiry/cancellation path to `run-stage.ps1 -Execute -OwnedLanesDrained -CoordinatedWindow`. Its shared origin precedes dispatch metadata processing; only bounded in-memory metadata is prepared outside the native primitive. File creation occurs in that primitive or the guarded controller. The dispatcher starts a **fresh controller process** suspended in its owned job. That controller independently validates the same lease, capability receipt, all inputs and all executable/source/content hashes before invoking a payload. The switches attest current coordination; they are not a reservation service. Create a new cancellation file to revoke the running lease. Never reuse a directory or synthesize a missing success receipt.

## Bounds and ownership

The PR72-only supervisor derives from reviewed source SHA256 `0ffb82e568a1ae7bce90e751621a2f994fa92a6e7cd13442f4d65aaada1092c6`. It leaves that source and PR71's pins untouched. It creates the entire controller suspended, assigns its owned Windows Job, binds native identity and sets `0x44`/Normal before resume. All controller Python/hash/filesystem/setup, payload and final reconciliation work runs beneath that one job. The worker runs in the same controller process; there is no nested supervisor or second cleanup budget. Output is capped at 1 MiB per stream. Only retained process/job handles grant termination authority. Termination and zero-survivor confirmation take priority over optional member telemetry; member queries are omitted from this cleanup path.

Fixed enclosing limits are admission 20, qualification 650, build 900, native 120 and render/input 220 seconds. Qualification must still contain all 600 quiet seconds. Native HUD retains its 90-second inner limit; input retains 180 seconds beginning at launch, including startup. Each case's monotonic origin precedes binding/setup/parsing. Completion at or beyond its deadline fails, including late natural exits. Cleanup has one aggregate five-second budget; a surviving child, forced cleanup, lease cancellation, incomplete output or uncertain final ownership fails acceptance. No grace period follows root exit.

The controller retains its console through all native Python/Git invocations, including final reconciliation, and releases only its own attachment in its finalizer. Releasing it in the same PowerShell host before those invocations produced a console-mode error before the intended policy rejection. The worker shares the controller process and does not detach it. The Python checker releases only its own attachment; redirected output remains captured. No console host is found or stopped by name. Finalizer work remains inside the original job/deadline; a late exit, failed release or survivor cannot establish acceptance.

The prepared watchdog is intended to bound a controller stalled in setup or after writing an inner receipt; the new controls must verify this before adoption. Native watchdog kernel/receipt APIs can still stall synchronously and fail on return; do not claim a hard guarantee for every possible OS API stall. Capability preparation precedes functional dispatch. The terminal export attests the already exited whole controller; no later controller acceptance check can invalidate it.
